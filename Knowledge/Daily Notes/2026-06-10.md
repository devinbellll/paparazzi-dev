## Afternoon — MFC Stack Revamp

Switch over to using the real guidance stack and debugged that and the autopilot building

Spent the rest of the afternoon debugging the value of thrust setpoint and how it gets through to stabilization.

- **Pivoted MFC guidance to a standard `provides guidance` variant:** dropped the bespoke `guidance_mfc_run_vert/horiz` + custom-autopilot machinery (`STACK_USE_MFC_GUIDANCE`, cond-based calls) for the six stock plug functions, so NAV uses the stock `run_guidance_control` block.
- **Config-time stack switch:** stack selection in `anton_mfc.xml` is now a paired 2-line swap (`guidance type` + `stabilization type`); both pairings (MFC→INDI, INDI→MFC) link clean for `nps`.
- **Fixed two refactor-surfaced bugs:** bug-028 (z_sp stuck at 0 — bespoke vert read a `z_ref` only filled by the `guidance_v_run()` it displaced; now plugs in at `guidance_v_run_pos`, z_sp ramps 0 → −2.0 m) and bug-029 (NaN throttle — shared `mfc_core` never initialised in the guidance stack; added `mfc_core_init()` to `guidance_mfc_init()`).
- **MFC-Z still won't lift (bug-032, unresolved this day):** real cause was the `in_flight` flag never flipping true, plus a hover constant set too low to command liftoff — the constant should be expressed in physical units. (The retro's "WLS thrust-units mismatch, ~58× too small / wrong sign" theory was a red herring.) Fixed 06-11.

## Questions Raised
- I thought G2 was related to the inertia of the propellor and therefore only effected moments on the derivative of the actuators? Here it's just added?
```C
/**
* Function that sums g1 and g2 to obtain the g1g2 matrix
* It also undoes the scaling that was done to make the values readable
*/
void sum_g1_g2(void)
{
	int8_t i;
	int8_t j;
	for (i = 0; i < INDI_OUTPUTS; i++) {
		for (j = 0; j < INDI_NUM_ACT; j++) {
			if (i != 2) {
				g1g2[i][j] = g1[i][j] / INDI_G_SCALING;
			} else {
				g1g2[i][j] = (g1[i][j] + g2[j]) / INDI_G_SCALING;
			}
		}
	}
}
```
