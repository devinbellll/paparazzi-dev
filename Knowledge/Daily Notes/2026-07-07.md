## Afternoon — Simulink First Order Actuator Improvements


Today I have been working on your suggestions with the yaw axis parameters given the issue with the actuator lag.

I first realized my implementation of the first order actuator may have been incorrect in the first place with a misplacement of the saturation. 

Additionally, I looked into the JSBSim implementation of the aircraft model to see what the difference between the actuator dynamics might be there.

JSBSIM
a) Lag filter → thrust and steady yaw torque
```
fcs/X_motor ──► lag_filter (c1 = 30 rad/s) ──► fcs/X_motor_lag
```
`fcs/X_motor_lag` is the *physical rotor state* (normalized thrust).

b) Washout filter → spin-up (transient) yaw torque
```
fcs/X_motor ──► washout_filter (c1 = 50 rad/s) ──► fcs/X_motor_d
```
A JSBSim washout is a high-pass `s·c1/(s + c1)` — `fcs/X_motor_d` is multiplied with the G2 matrix to get the actuator reaction counter torque

My new implementation of the first order actuator now includes the washout filtered derivate from JSBSim.
