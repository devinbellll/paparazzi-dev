Executed [[HEOL Stages 2+3 (heol Library and ANTON_HEOL Guidance)]] in full.
Continuation of [[MFC Decoupled Core Port (HEOL Stage 1)]] (committed this
session as `be655818a` in `paparazzi`, `eab4afa` in `paparazzi_dev`, including

## What changed

### `heol.c`/`.h` — the library (stage 2)

New `paparazzi/sw/airborne/firmwares/rotorcraft/stabilization/heol.{c,h}` +
`conf/modules/heol.xml` (dependency-only, mirrors `mfc_core.xml`). `struct
HeolParameters` embeds an `MfcParameters` and implements `u = u_ff + u_fb`:
`heol_init()` locks the embedded loop to `decoupled = true`,
`use_trajec_sp = false`, `setpoint = 0`; `heol_run(measure, trajectory_ref,
u_ff)` computes `epsilon = measure - trajectory_ref`, runs `mfc_siso_run` on
`epsilon`, and sets `command = u_ff + mfc.command[0]`. No changes to
`mfc_core.c`/`.h` — stage 1's structure already supported this exactly, as
sketched at the end of the stage-1 plan.

**Proven equivalent, not just written to spec.** A host-side harness (same
technique as stage 1: `heol.c` has the same two stubbable dependencies as
`mfc_core.c`, run inside `paparazzi-build:latest`) drove `heol_run` with
`u_ff=0` against a plain decoupled `mfc_core` loop tracking the trajectory
directly (`setpoint = trajectory_ref`), same gains, 4000 samples of a
multi-tone signal plus a small measurement disturbance: **byte-identical**,
`max_abs_diff = 0`. This is the proof that the `setpoint=0, measure=epsilon`
reformulation is exactly a decoupled tracker with the feedforward split out,
not an approximation.

### `guidance_heol.c`/`.h` — wiring into ANTON's guidance (stage 3)

New `paparazzi/sw/airborne/firmwares/rotorcraft/guidance/guidance_heol.{c,h}`
+ `conf/modules/guidance_heol.xml`, a structural mirror of `guidance_mfc.c`
(same plug-function seam, Butterworth filtering, mode-entry seeding, thrust
packaging) with `HeolParameters heol_gx, heol_gy, heol_gz` in place of
`MfcParameters`, and an explicit `u_ff` term at each `heol_run()` call:

- gx/gy: `u_ff = ACCEL_FLOAT_OF_BFP(gh->ref.accel.{x,y})` directly — command
  unit is already m/s², no inversion needed.
- gz: `u_ff = MODEL_MASS * (ACCEL_FLOAT_OF_BFP(gv->zdd_ref) - 9.81f)` — command
  unit is Newtons (NED, negative = up), so the flatness feedforward needs the
  mass/gravity inversion. At hover (`zdd_ref = 0`) this reduces to
  `-m*g`, matching `GZ_NOMINAL_HOVER_THROTTLE`'s existing convention.

Both feed off the reference model's `gh->ref.accel` / `gv->zdd_ref`, which
turned out to already exist and compile — built by the "flatness trajectory
setpoints" work after the stage-1 plan was originally sketched, and confirmed
during this session's exploration (`guidance_h_ref.c`/`guidance_v_ref.c`
Taylor-extrapolate them from jerk/snap between packets).

Telemetry deliberately **not** wired up this pass: `GUIDANCE_MFC`'s message
shape has no `u_ff` field, and hijacking it under a different meaning would
mislabel data in any existing MFC PlotJuggler config. Live tuning goes through
`dl_settings` (`heol_gx.mfc.{kp,kd,ki,alpha,...}` — note the extra `.mfc.`
hop through the embedded struct). A dedicated `GUIDANCE_HEOL` message is a
follow-up.

### `anton_heol.xml` + fleet registration

New aircraft, not a flag on ANTON_MFC — cloned `anton_mfc.xml`, swapped
`<module name="guidance" type="mfc"/>` → `type="heol"`, replaced the
`GUIDANCE_MFC` section with `GUIDANCE_HEOL` (u_fb gains only — u_ff has no
tunable defines, it's computed from the reference model). Stabilization stays
`type="mfc"` — HEOL is guidance-only scope this stage. Registered as
`ANTON_HEOL` (ac_id 219) in `conf/userconf/ENAC/conf_mfc.xml` — **not**
`conf/airframes/ENAC/conf_enac.xml`; ANTON_MFC/ANTON_ONELOOP/Hoops_111_MFC
actually live in the userconf file, confirmed by grep before registering.
Reuses the existing `flat_traj_demo.xml` flight plan and `mfc_flight_test.xml`
telemetry — no new flight-plan/telemetry work needed.

Starting u_fb tuning borrowed from ANTON_MFC's flight-tested decoupled gx/gy
(kp=2, kd=25) and coupled-equivalent gz (kp=16, kd=12) values — explicitly
documented in the XML as a starting point, not a claimed equivalence, since
u_fb only has to correct the residual left over after u_ff now.

## Verification

**Compile — all three targets link:**
```
ANTON_HEOL ap · ANTON_HEOL nps · ANTON_MFC ap (regression, untouched)
```
Hit one build error along the way: `conf/modules/heol.xml` originally put
`<header>` before `<dep>`, which `module.dtd` doesn't allow (fixed order:
`doc,settings*,dep?,header?,init*,...,makefile*`) — failed codegen with
`Unexpected tag : 'DEP'`, not an XML syntax error. Logged as `bug-249`, fixed
by reordering.

**SITL smoke test** (`./sim.sh ANTON_HEOL --no-build --nav "Start
Engine,Takeoff,+15,Flat_Traj_Demo,+10,Standby,+5"`, 300s): motors on and
`in_flight=1` throughout, **no NaN** anywhere in the 132MB log. Takeoff
transient (brief overshoot to z≈-3m, x/y≈0.2-0.5m during climb) settles by
t≈25s; for the remaining ~275s (including the `Flat_Traj_Demo` block — a
no-op today since `flat_traj_demo_data.h`'s table is still the all-zero
placeholder) the aircraft holds a tight hover: x/y within ±0.1m of origin,
z pinned at -2.00m ±0.01m. Confirms the HEOL guidance loop is stable with the
borrowed starting gains — no divergence, no growing oscillation.

Not yet done: the `heol_gx.epsilon`/estimator PlotJuggler inspection the plan
called for (needs the telemetry follow-up above, or NPS_SCOPE_VAR additions
to `guidance_heol.c` mirroring `guidance_mfc.c`'s `#ifdef SITL` block).
